Priority chart designs · 9 May 2026

Seven flagship views.
One visual system.

The 300-chart pipeline collapses to seven priority deliverables. Each one below is paired with a chart-type rationale and a code-level shape that would render it from your aggregated DataFrame.

The first thing a reader meets is a table, not a chart.

A table that anchors every downstream chart. Sample size, date range, episode count, female share, median age, and a tiny appearance-over-time sparkline live together so the rest of the report has shared context.

01Age at appearance — show comparison violin

Ridges sorted by median, the outlier surfaced by hue.

Replaces the side-by-side violin plot. Sorting by median makes the StarTalk shift visible without an annotation; the IQR shaded under each density carries the variance story that the old violin's symmetric shape obscured.

StarTalk sits 22 years above the cross-show median (75 vs 53). Among the German shows, the IQR widths are nearly identical (≈14–18 yr) — they differ in level, not shape.
Code shape. Per show: scipy.stats.gaussian_kde(ages) evaluated on a fixed 20–95 grid → ridge path. numpy.percentile for IQR rectangle. Sort key = median, color highlight only when median > mean+1σ.

02Female share over time — line chart

One question per chart: is the gender gap closing?

A small-multiple line chart, not a stacked area. The y-axis is bounded 0–60% so movement is visible; a horizontal 50% reference line shows how far each show is from parity. The combined trend is a thicker neutral line behind the per-show lines.

Female share of guests, by year
% of guests with known gender · 5-year rolling mean · 50% parity line in red · 9 German shows · 2003–2025
Read
Across all 9 shows, female share rose from ~22% (2008) to ~36% (2024) — but the gap to parity has stalled since 2020. Caren Miosga launched at parity-distance, while Markus Lanz sits ~10pp lower than the combined trend.
Code shape. df.assign(year=…).groupby(["show","year"]).female.mean().unstack().rolling(5).mean(); per-show line via fig.add_trace(go.Scatter(mode="lines")). The combined line is a separate, wider, semi-transparent trace; end-labels via annotations rather than legend.

03Party × gender — stacked bar

Composition along an ordered axis. Width = party volume.

Two encodings, decoupled: bar length = number of party-affiliated guests (so the FDP/AfD's smaller share is honest), and the colored split = gender mix. Parties laid out left-to-right by political spectrum so visual scan is meaningful.

Gender split within each party
% of guests known to be a member · width = unique guest count · parties on political spectrum L→R
Read
Grüne is the only party where female guest share approaches parity (47%). FDP and AfD are the most male-skewed (≈80% / 84%). The CSU is small in volume but very male.
Code shape. Pre-aggregate guests.drop_duplicates(["guest","party"]).groupby("party").gender.value_counts(normalize=False).unstack(); render as go.Bar(orientation="h") with barmode="stack". Order axis manually — alphabetical defeats the point.

04Guest co-appearance network — PageRank

Force-directed layout, sized by PageRank, edges by shared episodes.

A graph answers a question the heatmap can't: who sits next to whom? Nodes are guests, edges are co-appearances on the same episode, node area scales to PageRank, color encodes occupation cluster. Top 10 most-central guests are listed beside the canvas.

Read
A dense SPD/Grüne policy cluster (Lauterbach, Habeck, Klingbeil) anchors the center. A loose journalist ring orbits at the periphery — they bridge between the political and cultural clusters but rarely sit together.
Code shape. networkx.from_pandas_edgelist(co_appearances) → nx.pagerank(G) for size; nx.community.greedy_modularity_communities or domain rule for color; layout via fa2.ForceAtlas2. Render as Plotly scatter (nodes) + line traces (edges) so it stays interactive in HTML.

05Property distribution — overview table

The book of contents for the dataset.

For every Wikidata property: how many guests have it, how many distinct values, how concentrated the top values are, and what the top-3 values literally are. This is the table you'd want before deciding whether a property deserves its own chart.

Only 7 of 11 properties deserve flagship charts: occupation, gender, age, dob, citizenship, place of birth, Commons category. Below 30% coverage, the chart's main message is "we don't know" — better to surface the gap than to render it.
Code shape. One property_summary() helper that returns coverage, nunique, top-3 cumulative share, and the literal top-3 strings. Tier assigned by threshold rules — flow into the dispatcher that decides chart vs footnote.

06Occupation hierarchy — sunburst

Wikidata occupations roll up into ~6 meta-categories. Show the rollup.

A two-ring sunburst: inner ring = meta-category (Politics, Media, Academia, Arts, Business, Other), outer = the actual Wikidata occupation. Sequential within meta-category so siblings stay readable; the meta-category names anchor the eye instead of 30 rainbow rectangles.

07Cross-cutting principles

Four rules that all seven charts above obey.

# 1. Canonical orderings live in one module.
SHOW_ORDER     = canonical_order(by="appearances")
PARTY_ORDER    = ["Linke", "Grüne", "SPD", "FDP", "CDU", "CSU", "AfD"]
OCCUPATION_META = {"Politiker": "Politics", …}

# 2. One palette dictionary, used everywhere.
PAL = dict(
    seq_blue   = ["#f0f5fb", "#3a78b5", "#11355b"],   # volume
    div_mf     = ["#d97757", "#eee", "#3a78b5"],      # composition
    cat6       = ok_lab_categorical(n=6),                  # meta-occupation
    warn       = "#c0392b",                              # reference / outlier
)

# 3. Every chart carries a pre-computed headline string.
def render(df, *, kind, headline, question):
    fig = DISPATCH[kind](df, order=SHOW_ORDER, theme=THEME)
    fig.add_annotation(text=headline, xref="paper", x=0, y=1.08, …)
    return fig

# 4. Sparse properties (<5% coverage) emit a footnote, not a figure.
if coverage(prop) < 0.05:
    emit_footnote(prop)
