Design audit · five tables · five files

Stronger numbers, quieter chrome.

The five tables you sent are doing serious work — twelve shows, ten parties, sixteen Wikidata properties — but they all share a common ailment: decoration competes with the data. Coloured group headers, full grid lines, alternating stripes, italic captions, and overlaid bar fills each ask for attention before the reader has even located a row.

Below: eight cross-cutting issues, then a before / after redesign of the three table archetypes — a hierarchical stats table, a category heatmap, and a sparse coverage matrix. Same data, same colour key for the shows, but rebuilt so the numbers do most of the talking.

A · Cross-cutting

Eight habits worth dropping before touching any single table.

01

Headers as bunting

Each header group wears its own pastel — blue for Program, green for Episodes, peach for Guests. The colour carries no information, only mood. Use a small caption + thin rule for grouping. Reserve hue for data.

02

Full grid + zebra + borders

Every cell has a 1px outline, then odd/even rows are tinted, then a fat 4 px left border is added. Three redundant separators stacked. Keep one. Hairline horizontal rules are usually enough.

03

“138 (2 %)” in one cell

Two numbers, two semantics, smashed together with parentheses. Eyes have to parse twice; columns can't right-align cleanly. Split into two columns, or pick one and footnote the other.

04

Bars only on some columns

In the stats table, three numeric columns are plain right-aligned but two carry full-width gradient bars. The reader infers a hierarchy that isn't really there. Either every comparable column gets a sparkbar, or none do.

05

Arbitrary blue heatmaps

SPD–CDU–Grüne–FDP all encoded in the same off-the-shelf blue ramp, even though every party has a real, well-known colour. Use the party hue per column, or commit to a single neutral ramp.

06

Vertical text on the property matrix

Sixteen header labels rotated 90° force the reader to crane their neck and read bottom-up. Rotate −40°, or pivot the table so labels can sit horizontally.

07

Mid-tone fills + white text

The heatmap cells flip text from white to dark grey around the middle of the ramp — exactly where contrast is worst either way. Push the lower end paler so a single dark text colour always works.

08

Bold blue total bars

Totals are emphasised with a saturated blue fill that draws more eye than any individual data row. A single rule above + bold tabular figures says “total” cleanly.

What changed

  • Hue retired from chrome. The blue / green / peach group headers are gone; colspan + fills becomes a small mono caption with a single hairline rule.
  • One left dot, not a fat border. The show identity colour now lives as a 9 px circle next to the name — same key, less weight.
  • Total moved to the top and rendered with one rule above + one rule below, no fill. It still reads as the anchor row but does not out-shout the data.
  • Numbers right-aligned with tabular figures so the decimal columns visually align across rows; no more jagged left edge.
  • Two numbers, two cells. “331 (15 %)” becomes a primary percentage with a quiet count tucked behind in mono.
  • Sparkbar on every comparable column. A 2 px line at the bottom of each %-cell makes the rank readable in a single pass.

What changed

  • Each column lives in its party's hue. The SPD column ramps red, CDU charcoal, Grüne green, FDP yellow — real colour-meaning replaces an arbitrary blue.
  • Appearance + unique totals become a small mono caption under the party name, not their own heavy blue header rows.
  • A 3 px stripe sits under each party label so the column key reads without looking down at the cells.
  • Cell text stays a single dark ink at all intensities — light tail of each ramp guarantees contrast, no white/grey flip in the middle.
  • Borders dropped. One hairline between rows; no vertical chrome at all.
  • Empty cells render as a neutral dash, not a 0 %-coloured tile — absence is data, but it shouldn't compete with presence.

What changed

  • Headers rotated −40° instead of vertical. Same density, but legible without head-tilt and the row of labels now sits in a single readable band.
  • Columns clustered into tiers (well-covered → partial → sparse) with one black rule between tiers, so the eye finds “where the data thins out” instantly.
  • Avg. row pinned at the top of the body and bold, acting as the baseline every show is read against — instead of sitting hidden at the bottom in italic.
  • Single perceptual ink ramp (warm grey → deep ink) replaces the cool blue spectrum. Dark cells read as dark anywhere in the table.
  • 0 % cells are blank with an em-dash; nothing fights the dense end of the ramp.
  • Cell text always dark; the ramp tops out below the contrast cliff. No more black-on-mid-blue.
Closing rules

Six rules to apply across the whole set.

  1. One encoding per column. Number, bar, or colour — never all three. Decide what the column is for (lookup, comparison, scan) and pick one.
  2. Tabular figures, right-aligned. All numeric cells should use font-variant-numeric: tabular-nums and right-align — the decimal column has to line up.
  3. Hue only where hue means something. Show identity, party identity, sentiment. Never for header groups, totals, or row striping.
  4. Hairlines, not boxes. A single horizontal rule between rows beats a full grid. If a vertical rule is needed, use one to mark a tier boundary, not every cell.
  5. Totals via type, not fill. A rule above + bold weight reads as “total” without a saturated panel under it.
  6. Pick the rotation that keeps text horizontal. If a header doesn't fit horizontally, prefer a small −40° rotation over full 90°; better still, transpose the table.
